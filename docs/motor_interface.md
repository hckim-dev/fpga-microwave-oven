# STEP 9 모터 PWM Interface

`motor_controller`는 속도 설정과 PWM 주기를 관리하고, 가열 제어부의 실행 허가로
L298N의 ENA/IN1/IN2 논리 출력을 차단합니다. 실제 모터 RPM·토크·전류는 측정하지 않았습니다.
기존 실습의 카운터/비교기 원리를 활용하되 10 MHz 출력과 즉시 듀티 변경 방식은 재사용하지 않습니다.

## 포트와 Parameter

| 포트/Parameter | 계약 |
| --- | --- |
| `clk`, `reset` | 100 MHz와 동기 해제된 active-high Reset |
| `cook_state` | 기존 IDLE=0, RUN=1, PAUSED=2, DONE=3 |
| `run_enable` | 도어/정지/만료 조건을 반영한 가열 제어부의 실행 허가 |
| `button_pulse` | [1]=속도 증가, [2]=감소. [3..6]의 상위 우선순위 이벤트는 설정 차단 |
| `speed_level` | 요청 설정. 0/1/2/3 = 30/50/70/90% |
| `duty_percent` | 요청 설정의 백분율, 실제 RPM 또는 순간 적용 듀티가 아님 |
| `motor_pwm` | ENA용 active-high PWM |
| `motor_in1`, `motor_in2` | 한 방향 구동 시 1/0, 정지 시 0/0 |
| `PwmPeriodClocks` | 기본 100,000. 100 MHz에서 1 kHz |

`PwmPeriodClocks`는 10 이상의 10 배수여야 합니다. HIGH 길이는 주기의
30/50/70/90%로 정확히 계산되며 Simulation에서는 10 또는 20클럭 주기도 검사합니다.
Reset은 속도 50%와 모든 모터 출력을 LOW로 초기화합니다.

## 속도 설정과 주기 경계

IDLE/RUN/PAUSED에서 설정할 수 있고 DONE에서는 무시합니다. RUN에서 실행 허가가
없을 때도 설정을 받지 않습니다. 증가/감소 동시 입력은 유지하며 상한/하한에서 포화합니다.
취소·열기·닫기·KEY와 동시 입력이면 속도 변경을 무시합니다. 분/초 선택과 속도 변경은 독립적입니다.

요청 설정과 현재 주기의 적용 설정을 분리합니다. HIGH 중 감소해도 펄스를 자르지 않고,
LOW 중 증가해도 새 HIGH가 중간에 생기지 않으며 다음 주기부터 최신 설정을 적용합니다.
변경 입력이 주기 마지막 클럭에 들어오면 바로 시작하는 다음 주기에 반영합니다.
정지 중 변경한 설정은 다음 실행의 첫 주기부터 사용합니다.
취소와 자연 만료는 속도 설정을 보존하며 전체 Reset만 50%로 되돌립니다.

## 정지와 재시작

출력 조건은 Reset 해제 + RUN + run_enable입니다. 조건 상실은 주기 완료를 기다리지 않고
PWM과 방향 출력을 LOW로 차단합니다. 다음 클럭에 내부 주기를 초기화하고, 실행 허가가
다시 들어오면 새 PWM 주기를 시작합니다. IN1을 먼저 설정하고 첫 PWM은 다음 클럭에 시작합니다.
이는 RTL의 신호 순서이며 실제 모듈의 전기적 Timing을 측정한 결과는 아닙니다.

STEP 9에서 가열 제어부의 `run_enable`에도 현재 만료 조건을 추가했습니다.
만료와 속도 입력이 같은 클럭에 들어올 때 RUN의 이전 상태만 보고 다음 설정을 바꾸지 않도록
실행 허가를 먼저 차단하며, FSM·포트·기존 우선순위는 유지합니다.
외부 스위치에서 이 차단까지는 기존 동기화/debounce 지연이 존재합니다.

기존 배정은 ENA=JA1/J1, IN1=JA2/L2, IN2=JA3/J2이며 XDC와 결선은 변경하지 않았습니다.
L298의 Enable LOW는 브리지 비활성 조건입니다. 정지 논리 출력을 모터 축의 즉시 정지로
해석하지 않습니다. 근거: [ST L298 데이터시트, Pin description 및 Application information](https://www.st.com/resource/en/datasheet/l298.pdf).

## 실제 보드 확인 예정

1 kHz/듀티, 단방향 회전, 정지 후 관성, 각 단계에서 기동 가능한지와 실제 속도 변화를
확인해야 합니다. 특히 30% 설정이 부하에서 기동을 보장하지는 않습니다.
출력 듀티를 실제 RPM 비율로 표현하지 않으며 전원·Driver·모터의 전체 적합성은 미확인입니다.
STEP 9는 Simulation까지 진행했습니다. STEP 10에서 보드용 Top·XDC와 전체 논리 통합을
추가했으며 다운로드·실제 동작은 미확인입니다. [전체 통합](integration.md)을 참고하세요.

STEP 11의 Top은 SW0 잠금 중 속도 버튼 이벤트를 차단합니다. PWM·속도 제어부 자체의
주기·듀티·정지 규칙은 유지합니다. [조작 잠금](control_lock.md)을 참고하세요.
