# STEP 7 부저 제어 Interface

`sound_controller`는 버튼 BEEP, 도어 효과음과 종료 리듬을 한 출력으로 재생합니다.
모든 입력은 같은 `clk` 도메인의 논리 이벤트입니다. 실제 음량·음색·전류와
SM-1205C의 내부 발진 여부는 Simulation으로 확인되지 않습니다.

## 포트와 Parameter

| 포트/Parameter | 계약 |
| --- | --- |
| `clk`, `reset`, `tick_1ms` | 기존 클럭·Reset·1 ms enable |
| `button_pulse[6:0]` | 기존 버튼 순서. Reset 제외, 누름당 1클럭 |
| `door_open_event`, `door_close_event` | 실제 도어 제어에서 수락한 개폐 요청당 1클럭 |
| `alert_active` | 가열 FSM이 DONE이면 1 |
| `alert_on` | 표시부가 제공하는 종료 점멸 ON 구간 |
| `buzzer` | active-high 출력. 실제 부품에 맞는 전기적 구동 적합성은 별도 확인 |
| `sound_active` | carrier 적용 전 ON/OFF envelope |
| `busy` | BEEP·도어 효과음 재생/대기 또는 종료 알림 진행 중 |
| `queue_overflow` | 요청 용량 초과 sticky 표시. Reset/취소로 해제 |
| `BeepOnMs`, `BeepGapMs` | 기본 40/20 tick. BEEP 간 무음 간격 포함 |
| `DoorStepMs` | 기본 70 tick. 도어 효과음은 세 단계 |
| `PassiveBuzzer` | 기본 0=ON/OFF envelope, 1=carrier 출력 |
| `ToneHalfClocks` | 기본 25,000. 100 MHz에서 2 kHz, 50% duty carrier |

계수 Parameter는 양의 정수, 부저 모드는 0 또는 1을 사용합니다.
기본 모드는 리듬 신호를 정의한 것으로 보유 부저의 능동형 여부를 확정한 것은 아닙니다.
실제 부저 특성 확인 후 보드 Top에서 모드를 선택해야 합니다. 부품의 전류와 직결 적합성은
미확인 상태이며 XDC와 기존 결선을 이번 단계에서 변경하지 않았습니다.

## 리듬과 우선순위

| 종류 | 기본 패턴 |
| --- | --- |
| 버튼 BEEP | 40 ms ON, 20 ms 무음 |
| 열림 효과음 | 70 ms ON, 70 ms OFF, 70 ms ON |
| 닫힘 효과음 | 세 단계 연속 ON, 총 210 ms |
| 종료음 | FND와 같은 500 ms ON/OFF 3회, 총 3초 |

우선순위는 Reset > 취소 > 버튼 BEEP > 도어 효과음 > 종료음입니다.
버튼 BEEP은 도어 효과음의 단계/누적 시간을 보존하고 무음 간격까지 마친 뒤 이어 재생합니다.
종료음은 표시부의 시간 기준을 그대로 따르므로 다른 소리가 우선되어도 3초 기준은 계속
진행합니다. 완료된 종료음을 나중에 연장 재생하지 않습니다.
각 요청은 다음 클럭들에서 재생을 시작하며, ms 길이는 시작 후 공급된 유효 tick 개수로
정의합니다. 실제 시작 시각과 전역 tick 위상에 따라 벽시계 시간에는 최대 1 ms 미만 차이가 있습니다.

도어 원시 버튼은 BEEP만 요청합니다. 개폐 효과음은 이후 도어 FSM이 수락한 이벤트로
요청해야 하므로 이미 열린 문에 대한 열기 입력 등을 중복 효과음으로 처리하지 않습니다.
STEP 8의 `tb_door_control`에서 실제 도어 FSM 수락 이벤트를 연결해 효과음 재생과 중복 방지를
확인했습니다. STEP 7의 단위/연계 TB는 수락 이벤트를 직접 공급합니다.

## 입력 보존과 용량

- 버튼 이벤트는 대기 BEEP 최대 15개와 현재 재생 1개까지 보존합니다.
- 동시 버튼은 각각 계수합니다. 취소가 포함되면 다른 동시 입력보다 취소가 우선입니다.
- 도어 효과음은 4개 FIFO와 현재 재생 1개까지 보존합니다.
- 개폐 이벤트 동시 입력 시 FIFO에는 열기, 닫기 순서로 저장합니다. 실제 도어 제어에서는
  STEP 3의 열기 우선순위로 한 요청만 수락해야 합니다.
- 같은 클럭의 dequeue/enqueue는 먼저 빈자리를 반영하고 새 요청을 저장합니다.
- 초과 버튼은 포화시키고, 꽉 찬 효과음 FIFO의 새 요청은 버리며 overflow를 알립니다.
  무한 입력이나 임의의 빠른 연타를 무제한 보존하지는 않습니다.
- 취소는 현재/대기 재생을 모두 폐기한 뒤 취소 버튼 BEEP 한 개만 남깁니다.

## 표시 연계

`display_controller.alert_on`을 추가 출력으로 노출했습니다. FND의 0000 ON 조건과
부저 종료음이 같은 신호를 사용하므로 별도 3초 타이머를 만들지 않습니다.
기존 `alert_done`과 제어부의 상태 전이·우선순위는 유지했습니다.
기존 표시 TB도 새 출력에 연결해 종료 ON 구간과 완료 후 소등을 검사합니다.

실제 청취와 전압·전류 검증, 최종 보드 Top 연결은 아직 하지 않았습니다.
