RTL 13개 파일의 주석 27줄과 TB 14개 파일의 주석 32줄을 확인했습니다.
Python 8개·Tcl 3개·활성 XDC·gitignore의 주석/모듈 설명도 조사했습니다.
설계 의도·극성·스캔 순서·우선순위·기동 억제·명령 적용 시점처럼 코드만으로 놓치기 쉬운

직접 작성한 코드와 구분해 원문을 보존했습니다.

## 이름·구조·최적화 판단

- 파일과 모듈은 snake_case, Parameter는 기존 PascalCase, FSM 상수는 기존 대문자 규칙을 유지했습니다.
- 내부 r_는 저장 상태, w_는 조합 계산이라는 기존 구분을 유지했습니다. Verilog의 조합 reg도 w_에 해당합니다.
- Top 연결 신호·공개 포트·인스턴스·TB의 계층 참조 이름을 불필요하게 바꾸지 않았습니다.
- 입력 정규화·가열·표시·소리·도어·서보·모터의 책임과 단일 클럭 구조를 유지했습니다.
- Top의 button_down/duty_percent/timeout_pulse/sound_busy 등은 관찰·TB 연결에 쓰는 신호입니다.
  사용하지 않는 출력 포트를 없애기 위해 모듈 계약을 바꾸지 않았으며 합성에서 불필요한 논리는 제거됩니다.
- 상수 나눗셈을 BCD 카운터로 바꾸거나 FSM·FIFO·부저 모드를 재구성할 성능 근거는 없습니다.
  LUT 785개(3.77%), FF 436개(1.05%)와 Timing이 정리 전후 동일합니다.
- active 부저 모드의 반송파 제거와 모듈별 미사용 버튼 비트 경고는 기존 의도와 일치합니다.
  경고를 감추는 설정이나 dummy 로직은 추가하지 않았습니다.

부정 검사의 근거는 `build/review_runner_negative.py`와
`build/review_negative_timing_final_console.txt`입니다. 실제 정상 빌드와 별도 작업입니다.
외부 I/O output delay 미정의에 따른 TIMING-18 경고 32개는 남으며 내부 Timing 통과와 구분합니다.
원본 실기 결선과 보드에는 자동으로 기록하지 않았습니다.

Verible Language Server v0.0-4296-g0f262651의 formatter/parser로 27개 파일을 확인했습니다.
기본 lint의 SystemVerilog 권장 규칙(always_comb, task/function lifetime, parameter 타입,
배열 차원 축약)과 기존 FSM 명명 규칙 차이는 Verilog 문법 유지 관점에서 확인했습니다.
TB의 단일 PASS 문자열 길이와 0~5로 제한된 반복문의 case default 경고도 별도로 확인했으며,
기본 lint가 경고 0개라는 의미는 아닙니다. 규칙 억제 설정은 추가하지 않았습니다.
